# 首次使用与验收

## 普通用户

用户只需在已安装技能的 Codex 中指定聊天、时间范围和本地输出目录。若缺少范围，可以先检查已打开窗口并只问不能推断的范围信息。新手不必自己准备 JSON 或学习 agent；这些由 Codex 在捕获后生成。

最低运行环境：macOS、已登录微信、Node.js 20 或更新版本；OCR 还需要 Apple Command Line Tools，Swift 工具链不匹配时可用 Clang 后备路径。桌面控制能力由用户的 Codex 客户端提供，不随此技能安装。终端检查不能证明屏幕录制或辅助功能权限已可用，须进行一次实际 UI 读取。

若 doctor 报缺失：给出具体缺项和操作路径。安装 Node 或运行 `xcode-select --install` 需遵循宿主权限流程，不自动使用 sudo。桌面权限在 macOS 系统设置的“隐私与安全性”中配置；权限名与宿主版本可能不同。没有桌面能力时仍能处理用户提供的捕获材料，但不要称自动微信抓取可用。

## 第一次真实验收

使用 Sol（建议 high）或 Astra（建议 medium），选择一个用户授权的短范围，包含正常文字、同内容重复消息、引用和至少一张图片。验证：

- 范围起止与两次底部状态/明确终点有证据；日期跨天时不混淆。
- 每条消息作者和正文按画面核对；OCR 不独立作为作者依据。
- 引用能跳到正确消息；推定与未匹配状态清楚。
- 图片导出文件可打开；原图状态与 UI 证据一致。
- 再捕获一段有重叠的增量，旧消息不重收、合法重复不消失。
- 全量校验和阅读页搜索、过滤、跳转、图片通过。

在档案的 `SETUP-VALIDATION.md` 记录日期、macOS/微信版本、实际使用模型、UI 工具、权限结果、OCR 结果、范围与逐项结果。机器路径和聊天内容留在本地档案。区分 `synthetic-tests-passed` 与 `live-workflow-validated`；前者不能替代后者。截图/视频不能获取、姓名有歧义、原图无法证明都应记录，不“全部通过”掩盖局限。

本包发布前的自动测试只含合成素材。用户在自己机器的首次真实验收成功后，才切换日常 Sol + Luna 分工。微信、macOS、UI 工具或格式发生重要变化后重验受影响步骤。
