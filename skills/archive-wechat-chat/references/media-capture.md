# 图片保存与原图证据

每张图片属于一条消息：保留该消息发言人、时间、顺序及图片状态。合并转发内不一定提供原图；不能因抓到一张缩略图就说图片已完整归档。

1. 在已观察到的 UI 中打开对应图片查看器。等待加载；若明确出现“查看原图 / 下载原图”操作，调用后再等待完成并记录该证据。不要把“原始尺寸 / Original image size”缩放按钮当作原图下载。
2. 使用微信自身的“保存 / Save / 另存为”取得应用提供的文件，在保存面板选择档案目录的 `assets/`。文件名由消息 ID 和序号组成，保留正确扩展名。不要覆盖不同内容的同名文件。
3. 核查文件存在、非空、可解码，记录字节数、像素尺寸、SHA-256、保存方式、对应查看器/原图下载证据。散列和尺寸证明保存文件的身份，不证明它与发送端原始文件相同。
4. 没有明确原图获取证据时，即使保存了高分辨率文件，也标为“微信导出文件，原图未验证”。只有用户提供发送端文件/散列匹配或可确认的原图下载路径才能标原图已验证。
5. 失效、未下载、权限失败或仅缩略图可用时记录原因。最多尝试两次同一路径；保留剩余项，不循环点击。截图若保留，明确是 preview/screenshot，不能当 original。

状态字段以 [archive-schema.md](archive-schema.md) 定义为准。普通媒体保留每项记录，包括未取得文件项；用户要求略过或按下述规则跳过表情包时写明原因及数量。视频、语音、文件和表情包不能悄悄算成已保存图片，按可获取文件或未支持状态列出。

## 表情包

表情包不要求提取动态原文件。优先保留发言人、顺序、来源时间精度和文字占位：来源可辨文字可写 `[表情包：学习]`，不可辨则写 `[表情包]`；不猜表情含义，也不把占位当作原发文字。普通内嵌 emoji 与正文一起保留，不按表情包删除。

若已有该消息的截图证据，可保留 `kind:"sticker", status:"preview", source:"screenshot"` 的媒体记录及证据引用，`path` 可省略，明确未取得动态文件。这是保留消息和截图表示，不是原文件保存成功；仅凭 AX 标记不能虚称截图预览已保存。

处理困难时可直接跳过表情包文件获取，不为此反复打开查看器或延迟正文归档。若连整条表情消息也略过，在本轮记录原因、数量及本技能允许略过的处理规则；保留可核验的出现位置证据。不要静默遗漏。计数与完整性按 [schema](archive-schema.md#completeness-and-sticker-policy) 处理；不发明 `skipped` 等未支持的媒体状态，也不把主动略过写成微信过期或不可访问。增量重叠中的旧表情消息仍沿用已归档身份。

## 已观察的兼容性

在 macOS 微信 4.1.13 中，聊天历史的 Media / Image 可打开 Photos and Videos 查看器；`Save` 能打开 macOS 保存面板。该查看器的 `Original image size` 是显示尺寸操作，没有可证明下载发送端原图的证据。因此该路径只支持“保存微信当前提供的文件”，不能保证恢复原图，也不代表所有微信版本和记录类型。

在 macOS 微信 4.1.13 的 `merged_forward` 窗口中，AX 的 `Image` 项双击没有打开查看器；应检查当前截图里的图片缩略图，并依据当下画面确认位置后再双击，不硬编码坐标。成功打开 `Photos and Videos` 后，使用微信原生 `Save` 打开系统保存面板，界面显示已保存。两张图片均保存并通过解码检查：1424 × 1240 像素 PNG 和 1260 × 1771 像素 JPEG。文件来自原生保存，未使用聊天截图代替；尺寸和解码验证文件可读，但不证明发送端原图，两项状态都只能记为 `saved_unverified`。这些结果仅描述本次观察，不代表其他版本或窗口模式。
